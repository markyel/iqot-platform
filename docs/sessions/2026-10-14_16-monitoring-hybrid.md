## Что сделано

### Инфраструктура
- **Релеи почты.**
  - Устранены зомби-процессы (контейнер с `--init`); SMTP и IMAP вынесены из event loop в потоки; мёртвые IP Beget перебираются в случайном порядке с таймаутом коннекта 8 с.
  - Скрипт обновления — `deploy/relay/upgrade-relay.sh`.
  - Релей #2 заблокирован Beget по SMTP и выведен из почтового пула.
- **Исходящие каналы обхода сайтов.**
  - tinyproxy на relay1, relay2 и хостинге liftpages (`deploy/relay/provision-egress-proxy.sh`) + `EgressPool`.
  - Сайт закреплён за каналом; бан канала на домен — 72 ч; после двух банов сайт блокируется.
  - Потребности на расширение — `docs/monitoring-design.md` §10a.
- **Инцидент «диск 100 %» 15.10** (бинлог + 13,7 млн строк sitemap).
  - Бинлог: хранение 2 дня, `binlog_row_image=MINIMAL`.
  - Sitemap: потолок 60 тыс. адресов на сайт; проверки: кап на сайт за тик.
  - `DB_QUEUE_RETRY_AFTER=960`.
- **Служебные оповещения:** `ops:health-check` → Telegram. Токен и чат пользователь задаёт сам в `.env`.
- **ИИ-прокси (16.10).** Под нагрузкой nginx прокси отвечал 503 — до 23 % вызовов в час. В `OpenAIClassifierClient` добавлены 2 повтора с паузой и джиттером на 429/5xx; таймауты не повторяются.

### Мониторинг
- **Агрессивность** — `/manage/monitoring/settings`, пресеты Эконом / Стандарт / Быстрый / Максимум; на проде «Стандарт».
- **Ф2 — каталоги сайтов.** Индекс sitemap, сопоставление по адресу и заголовку карточки, индексация содержимого (очередь `monitor-index`, 14 воркеров).
- **Качество цен.**
  - Аналог по адресу или заголовку → mismatch.
  - Цены-заглушки сайтов снимаются.
  - emex.ru и маркетплейсы — в стоп-листе.
- **Масштаб.**
  - Без потолка поиска на программу.
  - Классификация по категории заказчика (`client_category`, не более одного вызова ИИ на категорию) вместо поштучного gpt-4o.
- **Ф3 «Гибрид».**
  - Проверочные письма к ценам сайтов, доверие к сайту (уровни 0–3), сверка КП из обычных заявок.
  - Тех. заявка `MON-…` в reports (`source='monitoring'`).
  - **Запросы КП поставщикам без цены на сайте:**
    - «по запросу» — всегда;
    - затем профильный пул IQOT, если у позиции меньше 3 цен;
    - ответы → `mp_kp_offers`.
  - **Письма** — по общим лимитам; размер письма = размер в обычной рассылке.
  - **Отправка** — только по активным hybrid-программам.
- **ItemScope (16.10, инцидент M02502).**
  - Позиция видит только страницы со своими кодами: `program_items.identity_codes`, `mp_listings.matched_codes`.
  - «Подозрительно» считается внутри варианта товара.
  - Разовый перевод — `monitoring:item-scope`.

### Рассылка
- **Одна позиция в письме:** `EMAILS_DAYPLAN_MAX_PER_EMAIL=1`, бэкап `.env.bak.k1-20261015`.
  - Замер 05.09–05.10 у одних и тех же получателей: 1,65 против 0,35 цены на 100 позиций; цен на одно письмо поровну.
  - Число писем ограничивают капы получателей, а не размер письма.

### Тарификация (решение владельца, вариант «Б»)
- Покрытая позиция в месяц.
- Позиция со свежим КП (не старше 60 дней) — ставка ×3, даже при наличии цен с сайтов.
- API отдаёт `plan.kp_price_multiplier`.
- Автоначисление (Ф4) **не сделано**.

## Открытые вопросы
- **Ф4: автоначисление мониторинга** (ставка, ×3 за свежее КП, включённые позиции).
- **Признак НДС.**
  - У 94 % цен сайтов НДС не указан.
  - Предложено: `vat_included` в `best_price`, колонка НДС для КП в CSV, признак НДС на уровне сайта.
  - Нужно решение, как считать сводку при неизвестном НДС.
- **Через 1–2 недели — отклик на одну позицию в письме** (по `sent_at ≥ 16.10`); при заметном замедлении — компромисс 2 позиции.
- **ИИ-прокси.** Проверить долю 503 после повторов. Если высокая — снизить параллелизм индекс-воркеров или поднять лимит nginx на прокси.
- **Мелкие и внешние хвосты:**
  - mzCorp должен передавать все OEM-номера в `oem_articles`;
  - релей #2: обращение в поддержку Beget;
  - Telegram-токен для оповещений;
  - повторная проверка отложенного режима Яндекса;
  - журнал изменений API — вкладкой в кабинете (по желанию).

## 1. Эксперимент «ящик на батч» (без меток)

**Идея владельца:** метки не нужны — ящик и есть метка. На батч из 1–2 позиций — новый ящик, письма всем поставщикам пула
в «живом» темпе, вся почта ящика пересылается в общий `info@` домена, ответ опознаётся по адресу «Кому».

**Решения владельца:**

| Параметр | Решение |
|---|---|
| Батч | 1–2 позиции одного типа/области; пара — однотипные; та же деталь из разных заявок — не пара; нет пары — 1 любая |
| Получатели / темп | все поставщики пула; 1 письмо в 5 мин с ящика; будни 9–18 МСК |
| Доля / объём | 20% позиций; ≤10 ящиков в сутки |
| Организации | резерв (Excel ExportBase), самая давно использованная, повтор можно; госсектор (фонды, ГУП, МУП, учреждения) — исключён |
| Персона | одно вымышленное ФИО → адрес, имя отправителя, подпись; телефон организации с изменённой одной цифрой |
| Срок ящика | дедлайн заявки + 7 дн; без дедлайна — 21 день; затем удаление в Beget |
| Лимиты получателя | для писем ветки +20% (потолок ×1.2, интервал ÷1.2); основная ветка свой потолок не превышает |

**Сделано (Ф1–Ф4):**
- Ф1 — резерв организаций `alias_org_reserve` + вкладка «Резерв организаций» на `/manage/senders/import` (загружено 50, активных 45).
- Ф2 — `BegetMailApi` (ключи `BEGET_API_*` в `.env` прода), домены `alias_domains` (prosnabz.ru: `info@`, приём на любые адреса),
  `AliasMailboxFactory` (+`PersonaFactory`), колонка `reports.senders.pool` (`main`/`alias`, подтверждено владельцем) —
  ящики ветки исключены из плана дня, назначения отправителей, ёмкости, Гибрида, прогрева, возврата, опроса IMAP, досылки.
- Ф3 — `AliasBranch` в `emails:plan-day` (флаг `ALIAS_EXP_ENABLED`, **выключен**); письма без меток (`Batch::$purpose='alias'`,
  `cleanTaglessSubject`); расписание `AliasWindow::slots` по дням, внутри дня диспетчер шлёт созревшим получателям.
- Ф4 — `ReceiveAliasInboxJob` (из `emails:receive-dispatch`): `info@` → ящик по `X-Original-To`/To → `IncomingEmailRouter::routeAlias`
  (In-Reply-To → `email_queue.email_service_response.message_id`, теперь пишется для всех писем; иначе по адресу/домену).
- Удаление ящиков по сроку — `alias-exp drop-expired` ежедневно 03:30 МСК.
- Команда `alias-exp status|api-check|domain-add|mailbox-create|mailbox-drop|release|watch|drop-expired|reserve-filter`.
- Админка — вкладка «Эксперимент: ящик на батч» (`/manage/emails/campaigns/alias`): батчи, ящики, сравнение веток, домены.

## 2. Тарификация мониторинга (Ф4 §11a)

**Решения владельца:**
- начисление с 15.10.2026;
- расчётный период совпадает с подпиской;
- списание еженедельно;
- нехватка средств — сначала предупреждение, потом пауза.

**Сделано:**
- `MonitoringBilling` + `monitoring:billing accrue|backfill|charge|status`; таблицы `mp_billing_days`, `mp_billing_charges`.
- **Начисление** — 23:50 МСК: (покрытые без КП × ставка + со свежим КП программы × ставка × 3) / 30, минус включённые в план
  (общие на клиента, сперва web).
- **Списание** — 00:20 МСК, если старейший несписанный день старше 7 дней или кончается период подписки.
  Баланс −, `trackSpending(monitoring)`, строка в месячном акте.
- **Нехватка средств:** `billing.warning` → через 3 дня пауза `paused_reason=billing` → после пополнения списание и снятие паузы.
- API: блок `billing` и `paused_reason` у программы (справочник, OpenAPI, CHANGELOG обновлены).
- Админка: карточка «Тарификация» во вкладке «Мониторинг цен».
- Начислено за 15–16.10: №1 Пилот 1 439,54 ₽, №3 mzCorp 542,67 ₽. Первое списание — 22.10.

**Разбор для владельца (mzCorp №3):**
- 676 покрытых из 728 → (675 × 22 + 1 × 66) / 30 = 497,20 ₽/сут (≈ 3 480 ₽/нед).
- Включённые в план 100 позиций сейчас уходят Пилоту. Если Пилот не тарифицировать — 423,87 ₽/сут у №3.
- Переменные расходы №3 в установившемся режиме ≈ 60 ₽/сут (перепроверка 7 071 страницы раз в 14 дн. ≈ 17 ₽,
  повторный поиск в Яндексе ≈ 34 ₽, письма/ИИ ≈ 5–10 ₽).
- Первичный поиск ≈ 1,6–1,8 тыс. ₽ разово, окупается за ≈ 4 дня.
- Главная статья расходов мониторинга — Яндекс sync (≈ 1 220 ₽/сут при 2 500 запросах).

## 3. Открыто

- Включить `ALIAS_EXP_ENABLED` — по итогам ответов на пробные батчи (предложено после первых ответов).
- Тарифицировать ли Пилот (№1) — вопрос владельцу (по дизайну пилот бесплатный).
- Оповещения в Telegram о нехватке средств: на проде не заданы `OPS_ALERT_TELEGRAM_*`, почта клиентам не настроена.
- Часы БД Beget отстают от сервера приложения на ~8 мин (письма уходят с этой задержкой) — NTP.
- Позиция 4303 (та же деталь, что 4304) уйдёт в основную рассылку: часть поставщиков получит про деталь два письма.
- Наблюдение за пробными батчами — `php artisan alias-exp watch` (cron сессии каждые 30 мин, живёт до конца сессии).

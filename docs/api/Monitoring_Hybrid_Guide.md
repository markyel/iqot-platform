# Мониторинг цен IQOT: подключение режима «Гибрид»

Версия документа: 15.10.2026 · Полный справочник API: [IQOT_API_Reference.md](./IQOT_API_Reference.md)

## 1. Что такое «Гибрид»

В базовом режиме мониторинга (`lite`) IQOT собирает **публичные цены с сайтов поставщиков**: находит страницы ваших товаров, сопоставляет их с позициями и регулярно перепроверяет цены.

«Гибрид» (`hybrid`) включает всё то же самое и **дополнительно работает с поставщиками по почте**. Он закрывает три пробела, которых нет у мониторинга сайтов:

| Ситуация | Что делает «Гибрид» | Что вы получаете |
|---|---|---|
| Цена на сайте есть, но насколько ей можно верить? | Выборочно просит поставщика подтвердить актуальность цены и наличие | Признак `email_confirmed` у цены; растёт уровень доверия к сайту (`site_trust_level`) |
| Товар на сайте есть, но вместо цены «по запросу» | **Всегда** запрашивает у этого поставщика КП со ссылкой на его страницу товара | Цена из КП (`kp`) на источнике этого сайта |
| У позиции меньше трёх цен | Запрашивает КП у профильных поставщиков IQOT по типу товара | Отдельные источники `source_type: "kp"` — цены поставщиков, у которых нет страницы товара |

Порядок работы по позиции: сначала проверяются цены сайтов и запрашиваются КП у поставщиков с ценой «по запросу». Если после этого цен всё ещё меньше трёх, подключаются профильные поставщики.

**Ваша компания поставщикам не раскрывается.** Письма отправляет IQOT со своих ящиков и от своего имени, так же как при обычных запросах КП.

## 2. Что нужно для подключения

1. **Тариф с мониторингом цен.** Проверить можно запросом `GET /monitoring/programs/{id}`: поле `plan.items_max` должно быть больше 0. Без мониторинга в тарифе создание программы вернёт `403 monitoring_not_available`.
2. **API-ключ.** Создаётся в кабинете: «API-ключи» (`/cabinet/api-keys`).
3. **Данные номенклатуры** — см. раздел 3.

## 3. Подготовка номенклатуры

От качества данных зависит, найдём ли мы товар и правильно ли подберём поставщиков.

| Поле | Важность | Рекомендации |
|---|---|---|
| `client_ref` | обязательно | Ваш постоянный код позиции (код из 1С, SAP и т. п.). По нему позиция обновляется |
| `name` | обязательно | Полное наименование, как его понимает поставщик: «Ролик натяжной двери кабины», а не «Ролик» |
| `article` | **очень важно** | Артикул **производителя** (OEM / MPN), например `KM713150G01`. Это главный ключ поиска. Не передавайте сюда внутренние коды учётных систем |
| `brand` | важно | Производитель: KONE, OTIS, Schindler… Помогает различать товары с одинаковым артикулом |
| `client_category` | **для «Гибрида» — обязательно на практике** | Ваша категория товара: `{"code": "...", "path": ["Лифты", "Запчасти", "Ролики"]}`. По ней IQOT определяет тип товара и подбирает профильных поставщиков для запроса КП. **Без категории позиция мониторится по сайтам, но профильным поставщикам запрос не уходит** |
| `unit`, `attributes` | по желанию | Единица измерения, характеристики |

Соответствие вашей категории и типа товаров IQOT устанавливается один раз на категорию. Если вы уже передавали эти категории в заявках (`/submissions`), соответствия переиспользуются.

## 4. Подключение по шагам

### Шаг 1. Создать программу в режиме «Гибрид»

```bash
curl -X POST https://iqot.ru/api/v1/monitoring/programs \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{
        "name": "Лифтовые запчасти — мониторинг",
        "price_mode": "hybrid",
        "target_freshness_days": 30,
        "site_refresh_days": 14
      }'
```

Ответ `201` содержит `program_id` (`mon_…`), статус `draft` и лимиты тарифа `plan`.

**Если программа уже есть в режиме `lite`**, переключите её:

```bash
curl -X PATCH https://iqot.ru/api/v1/monitoring/programs/mon_01M4… \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"price_mode":"hybrid"}'
```

### Шаг 2. Загрузить позиции

До 5 000 позиций за вызов. Большой каталог разбейте на части, каждой части дайте свой `Idempotency-Key`.

```bash
curl -X POST https://iqot.ru/api/v1/monitoring/programs/mon_01M4…/items \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -H "Idempotency-Key: lift-catalog-2026-10-15-part1" \
  -d '{"items":[
        {"client_ref":"LW-0001547","name":"Ролик натяжной двери кабины","brand":"KONE","article":"KM713150G01",
         "client_category":{"code":"cat-114","path":["Лифты","Запчасти","Ролики"]}},
        {"client_ref":"LW-0002478","name":"Кнопка СТОП с фиксацией","brand":"Schaefer","article":"P1EC400E40-K/E",
         "client_category":{"code":"cat-201","path":["Лифты","Электрика","Кнопки"]}}
      ]}'
```

Ответ `202` содержит `import_id`.

### Шаг 3. Проверить импорт и сопоставление

```bash
curl -H "Authorization: Bearer $KEY" https://iqot.ru/api/v1/monitoring/programs/mon_01M4…/imports/imp_01J9…
```

Дождитесь `"status": "done"` и посмотрите `errors`. Затем проверьте неоднозначные позиции:

```bash
curl -H "Authorization: Bearer $KEY" \
  "https://iqot.ru/api/v1/monitoring/programs/mon_01M4…/items?match_status=ambiguous"
```

Для позиций `ambiguous` уточните название и бренд и загрузите их заново с тем же `client_ref`.

### Шаг 4. Запустить программу

```bash
curl -X PATCH https://iqot.ru/api/v1/monitoring/programs/mon_01M4… \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"status":"active"}'
```

Почтовая работа ведётся только по программам в статусе `active` и режиме `hybrid`.

### Шаг 5. Забирать цены

Настройте регулярную синхронизацию через `GET …/prices` (не чаще раза в час):

```text
1. GET …/prices                       → полная выгрузка; сохраните server_time из первого ответа
   GET …/prices?cursor=<next_cursor>  … пока next_cursor не станет null
2. Дальше: GET …/prices?updated_since=<server_time> — только позиции, где что-то изменилось
```

Новое КП или подтверждение цены поставщиком тоже считается изменением: позиция попадёт в инкрементальную выгрузку.

Для разового анализа удобнее CSV-выгрузка `GET …/export` — она открывается в Excel.

## 5. Как читать результат

У каждой позиции есть массив `sources` — по источнику на поставщика.

**Цена с сайта, подтверждённая поставщиком:**

```json
{
  "source_type": "site",
  "supplier_domain": "liftsale.ru",
  "url": "https://liftsale.ru/…/km713150g01",
  "price": 4180,
  "flags": { "web_price": true, "email_confirmed": true, "kp": false },
  "email_confirmed_at": "2026-10-12T11:00:00+00:00",
  "site_trust_level": 2
}
```

**Сайт с «ценой по запросу», цена получена из КП:**

```json
{
  "source_type": "site",
  "supplier_domain": "lzpro.ru",
  "url": "https://lzpro.ru/…/p1ec400e40",
  "price": null,
  "price_kind": "on_request",
  "flags": { "web_price": false, "email_confirmed": false, "kp": true },
  "kp": { "price": 2950, "currency": "RUB", "vat_included": true, "received_at": "2026-10-14T13:20:00+00:00" }
}
```

**КП профильного поставщика без страницы товара:**

```json
{
  "source_type": "kp",
  "supplier_domain": "lift-komplekt.ru",
  "url": null,
  "price": null,
  "flags": { "web_price": false, "email_confirmed": false, "kp": true },
  "kp": { "price": 4650, "currency": "RUB", "vat_included": true, "received_at": "2026-10-14T13:20:00+00:00" }
}
```

**Сводка по позиции.** `summary` (лучшая, минимальная, медианная и максимальная цена) учитывает и цены сайтов, и КП: для каждого источника берётся цена сайта, а если её нет — цена КП. Поле `best_price.price_source` показывает, откуда лучшая цена: `web` (сайт) или `kp` (КП).

Важно знать:

- **Расхождение цены сайта и КП.** Если поставщик в КП назвал другую цену, показываются обе: цена сайта в `price`, цена КП в `kp.price`. Доверие к сайту при этом снижается, и он проверяется чаще.
- **Аналоги не засчитываются.** Если поставщик предложил аналог или замену, а не ваш товар, такое предложение не попадает в цены.
- **Отказ «нет в наличии»** учитывается как сверка наличия; цена при этом не появляется.

## 6. Сроки и объёмы

| Что | Как |
|---|---|
| Цены с сайтов | Первые — через несколько часов после запуска; дальше по мере поиска (порядка 600–1 900 новых позиций в сутки) |
| Письма поставщикам | В рабочие дни, в рабочее время (по Москве) |
| Ответы поставщиков | Обычно 1–5 рабочих дней. Запрос без ответа закрывается через 14 дней |
| Повторный запрос | Одного поставщика по одной позиции спрашиваем не чаще раза в 60 дней |
| Проверка цен сайтов | Выборочная: новые сайты проверяются по нескольким ценам, сайты с подтверждённым доверием — реже; при расхождении — чаще |
| Темп по большим каталогам | Письма идут в пределах общей почтовой ёмкости сервиса, по одной позиции в письме — так поставщики отвечают заметно чаще. Каталог в тысячи позиций обрабатывается постепенно, за несколько недель |

Поставщику, у которого «по запросу» много ваших позиций, письма приходят частями по мере свободной ёмкости, без перегрузки его почты.

## 7. Тарификация

| Позиция | Ставка в месяц |
|---|---|
| Без свежей цены | не оплачивается |
| Только цены с сайтов (в том числе подтверждённые поставщиком) | `plan.price_per_item` |
| Есть свежее КП поставщика (признак `kp`), с ценами сайтов или без них | `plan.price_per_item` × `plan.kp_price_multiplier` (3) |

- КП считается свежим 60 дней с момента получения.
- Позиция входит в покрытие (`items.covered`), если её последняя цена — с сайта или из КП — не старше `target_freshness_days`.
- `plan.items_included` позиций входят в абонентскую плату. Сверх них — по ставке, до потолка `plan.items_max`.
- Подтверждение цены сайта по почте без присланного КП не повышает ставку.

**Пример на тарифе «Старт» (ставка 25 ₽):** у позиции 2 цены с сайтов и 4 КП — 25 × 3 = **75 ₽ в месяц**; у позиции только цены с сайтов — **25 ₽**.

## 8. Управление

| Действие | Как |
|---|---|
| Приостановить всё, включая письма | `PATCH {"status":"paused"}` |
| Возобновить | `PATCH {"status":"active"}` |
| Вернуться к мониторингу только сайтов | `PATCH {"price_mode":"lite"}` — новые письма не отправляются, уже полученные КП продолжают отображаться |
| Убрать позицию | `DELETE …/items/{client_ref}` или загрузка с `"active": false` |
| Добавить или изменить позиции | Повторная загрузка `POST …/items` с теми же `client_ref` |

## 9. Чек-лист запуска

- [ ] В тарифе есть мониторинг: `plan.items_max > 0`.
- [ ] У позиций заполнены `article` (артикул производителя), `brand` и **`client_category`**.
- [ ] Программа создана или переключена с `"price_mode": "hybrid"`.
- [ ] Импорт завершён (`status: done`), ошибки в `errors` разобраны.
- [ ] Позиции `ambiguous` уточнены и загружены заново.
- [ ] Программа запущена: `"status": "active"`.
- [ ] Настроена синхронизация `GET …/prices` с `updated_since`.
- [ ] Ваша система учитывает `source_type`, `flags` и поле `kp` у источников.

## 10. Частые вопросы

**Узнают ли поставщики, для кого запрос?** Нет. Письма отправляет IQOT от своего имени.

**Можно ли выбрать поставщиков или исключить кого-то?** Через API — нет. Исключить поставщика или сайт можно через поддержку.

**Почему по позиции нет запросов профильным поставщикам?** Возможные причины:

- у позиции уже есть три и больше цен;
- не передана `client_category`;
- ещё идёт этап запросов поставщикам с ценой «по запросу»;
- профильных поставщиков этого типа товара пока нет.

**Почему у источника есть и `price`, и `kp.price`, и они разные?** Цена на сайте и цена в КП разошлись. Для закупки ориентируйтесь на КП: это прямое предложение поставщика.

**Где контакты поставщика?** В API передаётся домен поставщика (`supplier_domain`) и страница товара (`url`). По домену можно найти сайт и контакты.

**Сколько стоит переключение `lite` ↔ `hybrid`?** Переключение бесплатное. Повышенная ставка действует только для позиций со свежим КП.

Поддержка: api@iqot.ru. В обращении укажите `X-Request-Id` из ответа API.
